# AI Agent Instructions

## Project purpose

This repository will contain a personal portfolio website. Its objectives are to present the owner's background, technical competencies, academic projects, education, certifications, and professional connections accurately and professionally.

## Current status

- Current phase: Phase 1 — Project Initialization
- Website implementation: not started
- Visual direction: pending user-provided references
- Personal information: pending user-provided or explicitly authorized sources
- Next phase: Phase 2 — Personal Information Gathering, only after user direction

## Required workflow

Use a documentation-first, approval-based, vertical-slice workflow for every feature:

1. Analyze the request and identify unknown requirements.
2. Propose an implementation plan, affected files, technical decisions, and acceptance criteria.
3. Wait for explicit user approval before implementing the feature.
4. Implement only the approved scope as a complete vertical slice where practical.
5. Explain important changes in beginner-friendly language.
6. Test against the acceptance criteria and fix issues found.
7. Update relevant documentation to match the implementation.
8. Commit focused, tested changes with a descriptive Git message when requested or appropriate.

## Stack and architecture

- Primary stack: PHP, HTML5, CSS3, and vanilla JavaScript.
- Do not add frameworks, libraries, build tools, or dependencies unless the user explicitly approves a demonstrated need.
- Keep application logic, presentation, and data concerns separate.
- Prefer small, readable files and reusable PHP components only when they genuinely reduce duplication.
- Use semantic HTML, accessible interaction patterns, responsive layouts, and progressive enhancement.
- Do not establish a visual theme, UI layout, or design system until the user provides design references and approves a direction.

## Code quality and security

- Favor clarity and maintainability over cleverness or unnecessary abstractions.
- Follow conventional PHP, HTML, CSS, and JavaScript formatting and naming.
- Validate future input on the server and escape output for its rendering context.
- Keep code understandable for an IT college student with developing programming experience.
- Preserve existing behavior. Explain and obtain approval before removal or material behavior changes when appropriate.

## Content and scope rules

- Never fabricate personal details, project descriptions, achievements, credentials, links, or employment history.
- Do not infer missing requirements; ask concise questions when an answer materially affects the result.
- Do not collect information from GitHub, LinkedIn, or other sources without explicit user authorization.
- Do not modify unrelated files while implementing a scoped task.
- Do not mark a feature complete without proportionate testing.

## Documentation and Git

- Keep README.md, DEVELOPMENT_PLAN.md, and CHANGELOG.md synchronized with actual work and approved decisions.
- Record meaningful user-visible or architectural changes in CHANGELOG.md.
- Review the working tree before edits. Do not overwrite user changes.
- Keep commits narrow and descriptive; avoid unrelated changes in one commit.
